# 復古零食店技術文檔

## 文件目的

本文件整理 Retro Snacks Shop 目前實際使用的前後端技術、第三方服務、部署方式、主要頁面與 API。內容以目前專案檔案為準，不包含尚未導入的軟體。

## 前端頁面

### 首頁 index.html

- 商品資料由 `GET /api/products` 載入。
- 支援分類與搜尋同時篩選、結果數、清除條件及零筆結果提示。
- 商品介紹彈窗顯示圖片、價格、描述、數量、口味與 Sketchfab 連結。
- 收藏儲存在瀏覽器 `localStorage`，目前不會跨裝置同步。
- 登入、註冊與驗證表單支援 Enter 送出、防重複送出及 Esc 關閉。
- Banner 輪播到 `banner2.png` 時可前往洞洞樂頁面。

### 會員資料頁 profile.html

- 使用 JWT 呼叫 `GET /api/user/me` 取得目前會員。
- 使用 `PUT /api/user/update` 更新生日、電話與偏好。
- 更換大頭貼目前只有介面，尚未實作上傳與資料庫欄位。

### 洞洞樂頁 hole-game.html

- 未登入使用者只能看到登入提示。
- 已登入會員每天可遊玩一次，日期依 `Asia/Taipei` 判斷。
- 頁面會顯示當日結果與最近 30 筆個人紀錄。
- 折價券目前只顯示結果，尚未連接購物或折抵流程。

## 前端 API 設定

`config.js` 集中提供 `window.RETRO_SNACKS_CONFIG.API_URL`：

| 執行位置 | API URL |
| --- | --- |
| `localhost` 或 `127.0.0.1` | `http://localhost:3000/api` |
| 其他主機 | `https://retro-snacks-v2.onrender.com/api` |

Render 網址異動時應優先修改 `config.js`，避免在各頁面分散設定。

## 後端架構

### Middleware

- `express.json()`：解析 JSON request body。
- `cors()`：目前允許所有來源，正式環境可改成只允許 GitHub Pages 與本機網址。
- `authenticateToken()`：驗證 `Authorization: Bearer <token>`。

### MongoDB models

| Model | Collection | 用途 |
| --- | --- | --- |
| `User` | `users` | 會員、密碼、Email 驗證與個人資料 |
| `Product` | `products` | 商品與 3D 模型連結 |
| `HolePrize` | `holeprizes` | 洞洞樂獎品與權重 |
| `RewardRecord` | `rewardrecords` | 每日遊玩與中獎紀錄 |

完整欄位與索引請參考 `docs/資料庫排版.md`。

### API 路由

| Method | Path | 需 JWT | 用途 |
| --- | --- | --- | --- |
| GET | `/api/products` | 否 | 取得全部商品 |
| POST | `/api/register` | 否 | 建立會員、產生驗證碼並寄信 |
| POST | `/api/verify` | 否 | 驗證 Email 驗證碼 |
| POST | `/api/login` | 否 | 驗證帳密並簽發 JWT |
| GET | `/api/user/me` | 是 | 取得目前登入會員 |
| GET | `/api/user/:username` | 是 | 舊版相容路由，只允許讀取自己 |
| PUT | `/api/user/update` | 是 | 更新生日、電話與偏好 |
| GET | `/api/hole-game/status` | 是 | 查詢今天是否已遊玩及今日結果 |
| GET | `/api/hole-game/records` | 是 | 取得最近 30 筆個人遊玩紀錄 |
| POST | `/api/hole-game/play` | 是 | 抽獎並建立每日唯一紀錄 |

## 環境變數

Render 正式環境至少需要：

```env
MONGODB_URI=<MongoDB Atlas connection string>
JWT_SECRET=<long random secret>
SENDGRID_API_KEY=<SendGrid API key>
SENDGRID_FROM_EMAIL=<verified sender email>
SENDGRID_FROM_NAME=Retro Snacks Shop
PORT=<Render provided port>
```

- `.env` 不可提交到 Git。
- 本機與 Render 都必須設定 `JWT_SECRET`。缺少、空白或使用舊預設值 `dev_jwt_secret_change_me`（含前後空白）時，後端會在連線資料庫與監聽連接埠前拒絕啟動，不依賴 `NODE_ENV`。
- 本機可將密鑰放在 `backend/.env`，並從 `backend/` 執行；Docker 目前將該目錄掛載到 `/app`，由 dotenv 載入。Render 請使用服務的環境變數設定。不要提交密鑰；更換密鑰會使舊 JWT 失效，會員需重新登入。
- 未設定 SendGrid 變數時，註冊信無法寄出。

### 驗證 API 輸入規則

- `POST /api/verify` 僅接受非空白字串 `username` 及六位 ASCII 數字字串 `code`，格式不符時回傳 400，不查詢資料庫。
- 一般驗證碼必須符合帳號及代碼，且 `codeExpires` 是有效、尚未到期的日期。成功後清除驗證碼及期限，不能再次使用同一一般驗證碼。
- 測試碼 `000000` 仍保留，會通過既有帳號的測試驗證並略過期限，但同樣必須通過輸入格式檢查。正式上線前仍須移除或限制。

## 本地開發

### Docker Compose

```powershell
docker compose up --build
```

| Service | Port | 用途 |
| --- | ---: | --- |
| `app` | 3000 | Node.js API |
| `db` | 27017 | 本機 MongoDB |

如果後端套件更新但匿名 `node_modules` volume 沒有更新，可執行：

```powershell
docker compose up --build --force-recreate --renew-anon-volumes
```

### 不使用 Docker

```powershell
cd backend
npm install
npm run dev
```

前端可使用 Live Server，或在專案根目錄執行：

```powershell
python -m http.server 5500
```

## 後端安全回歸測試

從專案根目錄執行：

```powershell
npm test --prefix backend
```

使用 Node.js 內建測試工具，測試檔為 `backend/test/security.test.js`。目前有 33 項測試，執行實際伺服器原始碼並隔離資料庫、環境檔、寄信及連接埠；涵蓋驗證 API 與 JWT 設定，不是完整 HTTP、MongoDB 或部署整合測試。

## 部署流程

```text
GitHub main
  ├─ GitHub Actions --> GitHub Pages 靜態前端
  └─ Render Web Service --> Node.js API
                              |
                              ├─ MongoDB Atlas
                              └─ SendGrid Web API

瀏覽器 --> Sketchfab 商品模型
```

- `.github/workflows/static.yml` 目前上傳整個 repository 作為 Pages artifact，包含 `backend/` 與 `docs/`。
- Render 是否自動部署由 Render 服務設定決定；後端部署後會以 `initialProducts` 與 `initialHolePrizes` upsert MongoDB。
- `backend/Dockerfile` 目前以 `npm run dev` 啟動 nodemon，正式部署較適合改為 `npm start`。
